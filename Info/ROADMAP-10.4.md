# Схема реализации шага 10.4 — звуки наград за баллы каналов

Рабочий документ: как сделать пункт **10.4** из `ROADMAP.md`

> **10.4. Звуковые мемы внутри сообщений (`[смех]`, `[гонг]`):** возможность
> разрешить для донатов или наград за баллы каналов вставку коротких звуковых
> эффектов из библиотеки звуков. Размер M, правим `DesktopApp.tsx` и
> `SoundsPanel.tsx`.

Этот документ — только план и схема. Код по нему пишется отдельными коммитами
(раздел «План коммитов»), каждый шаг заканчивается рабочей сборкой
(`npm run lint && npm test && npm run build`).

> **Статус: часть А сделана** (шаги 10.4-1 … 10.4-6). Что из плана изменилось
> по ходу реализации:
> - звука «по умолчанию для всех наград» в настройках нет вовсе — у награды
>   без правила звук не играет (решение владельца проекта);
> - правила лежат отдельным блоком настроек `rewardSounds`, а не внутри
>   `eventSounds`: строка «Награда за баллы» из «Звуков событий» убрана;
> - свои файлы для наград — отдельная библиотека (`customRewardSounds`),
>   в обычных уведомлениях они не предлагаются;
> - звук уходит в OBS событием `reward.sound` по SSE, файлы приходят в виджет
>   один раз списком (`widget.rewardSounds`) — страница играет их сама тем же
>   проигрывателем, что и окно приложения.
> - список наград авторизованного канала подтягивается сам (после входа и
>   кнопкой «Обновить»): новые награды получают пустую строку правила, уже
>   настроенные не трогаются, звук держится за наградой по её id.
> Осталось: часть Б (звуковые мемы `[смех]`, `[гонг]`) — шаги 10.4-7 … 10.4-9.

## 1. Что именно делаем

Две связанные возможности, общий механизм — «вставить звук из библиотеки в
момент события»:

| Часть | Что видит стример | Где включается |
|---|---|---|
| **А. Звук награды за баллы** (главная просьба) | при активации награды за баллы канала играет короткий звук; у каждой конкретной награды может быть свой звук | «Звуки уведомлений» → «Звуки событий» → «Награда за баллы» |
| **Б. Звуковые мемы в тексте** | в тексте доната или заявки на награду маркер `[смех]` / `[гонг]` — играет соответствующий звук из библиотеки | «Звуки уведомлений» → «Звуковые мемы» |

Часть А полностью закрывает «звуки за баллы каналов». Часть Б — тот же самый
пункт роадмапа, но про маркеры внутри текста; делается второй и зависит от А.

**Осознанно не делаем:** вывод этих звуков в оверлей/OBS (звук живёт в окне
приложения; для OBS это отдельный пункт 4.2 «Алерты»), озвучку маркеров
голосом (наоборот — маркеры надо убирать из текста перед чтением, см. раздел 6).

## 3. Схема данных

### 3.1. Название награды должно быть структурным полем

Сейчас имя награды известно только из текста («активировал награду «Гонг»»).
Привязывать звук разбором текста — хрупко: любая правка формулировки ломает
настройки стримера. Поэтому:

**Хост (`webview2/Connectors.cs` + `webview2/HostApi.cs`):** в `ChatEvent`
добавляются необязательные поля:

```csharp
/// Награда за баллы канала: структурные данные вместо разбора текста.
public string? rewardTitle { get; set; }   // Twitch: reward.title
public string? rewardId    { get; set; }   // Twitch: reward.id (устойчивее названия)
public int?    rewardCost  { get; set; }   // Twitch: reward.cost, если площадка отдаёт
```

Twitch EventSub `channel.channel_points_custom_reward_redemption.add` отдаёт
`reward.title`, `reward.id`, `reward.cost`, `prompt`, `user_input` — подписка
на это событие уже есть (`Connectors.cs`, список топиков EventSub), новых
прав не нужно. VK Play отдаёт имя награды в `reward.name` / `reward.title`.
Остальные площадки наград за баллы не присылают — для них работает звук по
умолчанию.

**Фронтенд (`src/lib/types.ts`):** в `ChatMsg` добавляется такое же
необязательное поле:

```ts
/** Награда за баллы канала (kind === "reward"). */
reward?: {
  title?: string;
  /** идентификатор награды на площадке — устойчивее названия */
  id?: string;
  /** стоимость в баллах, если площадка её передаёт */
  cost?: number;
};
```

Поле необязательное — старые сообщения, виджет OBS и оверлей не ломаются,
фикстуры и демо продолжают работать.

**Нормализация (`DesktopApp.tsx`, блок `chat.message`):** поля копируются из
события хоста в `ChatMsg` рядом с существующими (`amount`, `currency`, …).

### 3.2. Индивидуальные звуки — внутри существующей настройки события

Рекомендуемый вариант (А): расширить правило события, а не заводить второй
ключ настроек. Так остаётся один тумблер и один «звук по умолчанию», а
индивидуальные награды живут рядом с ними.

```ts
/** Свой звук для конкретной награды за баллы канала. */
export interface RewardSoundRule {
  /** название награды, как на площадке (сравнение без учёта регистра и пробелов) */
  title: string;
  /** идентификатор звука: встроенный или `custom:<id>` */
  sound: string;
  /** громкость 0–1 */
  volume: number;
}

export interface EventSoundRule {
  enabled: boolean;
  sound: string;
  volume: number;
  /** только для события «Награда за баллы»: свой звук у конкретной награды */
  rewards?: RewardSoundRule[];
}
```

Пример сохранения (`settings.json`, ключ `eventSounds`):

```json
{
  "reward": {
    "enabled": true,
    "sound": "boing",
    "volume": 0.6,
    "rewards": [
      { "title": "Гонг", "sound": "bell", "volume": 0.8 },
      { "title": "Highlight my message", "sound": "custom:1712345678901", "volume": 0.7 }
    ]
  }
}
```

Ограничения: не больше **50** правил (размер настроек и вменяемый список),
пустые и дублирующиеся названия не сохраняются.

*Альтернатива (Б), если не нравится поле `rewards` у всех событий:* отдельный
ключ `rewardSounds` со своей структурой. Минус — два места в интерфейсе
настраивают один и тот же звук, и старый тумблер «Награда за баллы» придётся
либо удалять (ломая сохранения), либо объяснять, что он больше не работает.

## 4. Логика выбора звука

Чистая функция в новом модуле `src/lib/rewardSounds.ts` — без React и без
звука, поэтому её можно покрыть юнит-тестами:

```ts
/** Нормализация названия награды: регистр, лишние и неразрывные пробелы. */
export function normalizeRewardTitle(title: string | undefined): string;

/** Запасной путь: вытащить название из текста «активировал награду «Имя»: …». */
export function rewardTitleFromText(text: string | undefined): string;

/**
 * Какой звук играть при активации награды.
 * Порядок: индивидуальное правило → звук по умолчанию → тишина.
 */
export function resolveRewardSound(
  msg: Pick<ChatMsg, "kind" | "text" | "reward">,
  rule: EventSoundRule | undefined,
): { sound: string; volume: number } | null;
```

Правила разрешения:

1. `rule.enabled === false` → `null` (молчим, никаких исключений).
2. Название награды: `msg.reward?.title`, если пусто — `rewardTitleFromText(msg.text)`
   (совместимость с хостом, который ещё не присылает структурное поле).
3. Ищем первое правило, у которого `normalizeRewardTitle(r.title) === title`.
   Совпало → его `sound` и `volume`.
4. Не совпало → `rule.sound === "none" ? null : { sound: rule.sound, volume: rule.volume }`.
5. Неизвестный идентификатор звука (`custom:...` удалён из библиотеки) →
   `playDonateSound` сам молчит, настройку не затираем.

Сравнение **точное по нормализованному названию**, без «похожести»: стример
должен понимать, почему звук сработал именно так. Регистр, лишние пробелы и
неразрывные пробелы игнорируются.

Подключение в `DesktopApp.tsx` — в существующей ветке `notifyEventSound`,
которая уже вычисляет `key = "reward"`:

```ts
if (key === "reward") {
  const picked = resolveRewardSound(m, map.reward);
  if (!picked) return;
  if (!allowRewardSound()) return;      // общая пауза между сигналами
  playDonateSound(picked.sound, picked.volume);
  return;
}
```

### 4.1. Защита от каскада звуков

- **Общая пауза между сигналами наград** (`cooldown`, по умолчанию 1 c):
  отдельный `useRef` с временем последнего сигнала, как у `msgSoundAtRef`
  для звука сообщений. Иначе десять наград подряд превращаются в кашу.
- **Не прерывать, а пропускать:** звук донаты/события не должен обрывать
  предыдущий — пришедший сигнал просто не играет, если пауза не вышла.
- **Дедупликация VK Play:** коннектор VK присылает награду двумя событиями —
  `kind: "reward"` и дублирующим `kind: "chat"` с тем же текстом
  (`Connectors.cs`, комментарий «текст награды дополнительно показываем как
  обычное сообщение»). Звук награды играет только на `kind === "reward"`,
  маркеры из части Б тоже ищем только в `donate`/`reward` — второй раз звук не
  срабатывает.

## 5. Интерфейс (`SoundsPanel.tsx`)

В существующей строке «Награда за баллы» раздела «Звуки событий» под тумблером
и `SoundPicker` появляется блок:

```
Награда за баллы                                    [тумблер]
активация награды канала
[Звук по умолчанию для всех наград: чипы звуков]   Громкость ───●───

Свои звуки у конкретных наград                [+ Добавить награду]
  Гонг                       [bell ▾]  [▶]  [×]
  Highlight my message       [custom:гимн ▾] [▶] [×]

Подсказка: название награды должно совпадать с названием на Twitch/VK.
Недавние награды за сессию: [Гонг] [Highlight my message]  ← быстрые чипсы
```

Что нужно в коде:

1. `patchEvents({ reward: { ...rule, rewards: [...] } })` — добавление,
   переименование, удаление правила; изменение звука/громкости правила.
2. Поле ввода названия + `SoundPicker` (уже есть) + ползунок громкости (уже
   есть) + кнопка прослушать (`playDonateSound(id, volume)` по клику — это
   же поведение у чипов `SoundPicker`, его и берём; отдельно закрывает
   пункт **UI-4.4** «кнопка предпрослушивания у каждого звука»).
3. **Чипсы недавних наград:** `DesktopApp` копит названия наград из ленты за
   сессию (`Set` нормализованных названий, последние 10) и передаёт в
   `SettingsShell` → `SoundsPanel` пропсом. Клик по чипсу создаёт правило с
   уже заполненным названием — стримеру не нужно вручную копировать название
   с Twitch. Если полей `reward.title` ещё нет (старый хост), чипсы просто
   не появляются.
4. Пустое состояние: «Пока ни одной награды за баллы не активировалось —
   играет звук по умолчанию».

Настройки лежат в `eventSounds`, поэтому в `SettingsShell` и `HostApi.cs`
никаких новых ключей и миграций не появляется.

## 6. Часть Б — звуковые мемы `[смех]`, `[гонг]`

Отдельный модуль `src/lib/soundMemes.ts` (чистые функции + тесты):

```ts
export interface SoundMeme {
  /** код маркера без скобок: «смех», «гонг» */
  code: string;
  /** что играть */
  sound: string;
}

/** Маркеры из текста → идентификаторы звуков (в порядке появления). */
export function findSoundMemes(text: string, dict: SoundMeme[]): string[];
```

Поведение:

- Маркер — это `[код]` в тексте **доната** (`kind: "donate"`) или **заявки на
  награду** (`kind: "reward"`). В обычных сообщениях чата — не ищем: иначе
  любой зритель одним символом включает звук (спам-вектор).
- Сравнение без учёта регистра и лишних пробелов; неизвестные маркеры молча
  игнорируются; не больше **3** звуков на сообщение.
- Словарь по умолчанию (можно менять и дополнять в настройках):

  | маркер | звук |
  |---|---|
  | `[смех]` | `boing` |
  | `[гонг]` | `bell` |
  | `[аплодисменты]` | `fanfare` |
  | `[барабаны]` | `arcade` |

- Настройка: ключ `soundMemes` = `{ enabled: boolean; items: SoundMeme[] }`,
  по умолчанию `enabled: false` (как и все звуки событий).
- Порядок воспроизведения: сначала звук события (донат/награда), через ~250 мс
  маркеры по порядку — иначе два звука накладываются друг на друга.
- В интерфейсе — небольшой блок «Звуковые мемы» в `SoundsPanel.tsx`: тумблер,
  список пар «маркер → звук» с `SoundPicker`, добавление и удаление.

## 8. Экстренное глушение (обязательный подшаг)

Сейчас «Panic Mute» обрывает только озвучку: `ttsBridge.clear()` + очистка
очереди. Звуки донатов, событий и наград продолжают играть — при живой катке
это как раз тот случай, когда всё должно замолчать мгновенно.

В `src/lib/donateSounds.ts`:

```ts
/** Играющие сейчас свои звуки — чтобы иметь возможность их оборвать. */
const playing = new Set<HTMLAudioElement>();

/** Экстренное глушение всех звуков уведомлений (Panic Mute). */
export function stopAllSounds() {
  for (const el of playing) { try { el.pause(); } catch { /* noop */ } }
  playing.clear();
  // Встроенные звуки синтезируются в общем контексте: приостанавливаем его,
  // следующий звук сам разбудит (audio() вызывает resume()).
  if (ctx) { try { void ctx.suspend(); } catch { /* noop */ } }
}
```

`playCustom` регистрирует элемент в `playing` и убирает его по `ended`/`error`.

В `DesktopApp.tsx` в обработчик `onPanic` (и в хоткей `stopSpeech`)
добавляется `stopAllSounds()`.

- регистр и пробелы внутри скобок;
- неизвестный маркер игнорируется;
- маркер внутри слова/ссылки не срабатывает;
- пустой словарь → пусто;
- больше 3 маркеров → не больше 3 звуков.

Проверка вручную (браузерное демо без хоста): тумблеры в «Звуках уведомлений»,
клик по чипам звуков (слышно сразу), кнопки прослушивания в правилах наград.

## 11. Критерии приёмки

1. Награда за баллы играет звук по умолчанию, когда включен тумблер
   «Награда за баллы».
2. У конкретной награды свой звук — он играется вместо умолчанию; название
   совпадает при другом регистре и лишних пробелах.
3. Звук по умолчанию выключен (`none`), а индивидуальные правила работают.
4. Серия наград не даёт каскада: между сигналами есть пауза.
5. «Panic Mute» мгновенно глушит и звуки, не только озвучку.
6. Награда VK Play (два события) даёт ровно один звук.
7. Старый хост без структурных полей: награды определяются по тексту, звук по
   умолчанию работает.
8. Удалённый свой звук (`custom:…`) не ломает настройки и не роняет приложение.
9. `npm run lint && npm test && npm run build` зелёные на каждом шаге.

## 12. Риски и как их закрываем

| Риск | Решение |
|---|---|
| Название награды меняется стримером на Twitch — правило перестаёт совпадать | хранить `rewardId` в правиле (когда хост его присылает) и совпадать по id, название — только для показа и запасного пути |
| Площадка не присылает структурные поля | разбор текста как fallback + звук по умолчанию |
| Звуки накладываются друг на друга | общий cooldown, максимум 3 мема на сообщение, задержка 250 мс |
| Звук в браузере молчит до первого клика | существующее поведение `audio()` (resume после жеста); в десктопной сборке жест уже был |
| Раздувание настроек | в правилах хранятся только идентификаторы звуков, не файлы; лимит 50 правил |
| Лишние перерисовки ленты | разрешение звука происходит один раз на сообщение в `speakNow`, как и сейчас |
| Маркеры начинают зачитывать голосом | вырезание маркеров в `sanitizeForSpeech` в том же шаге, что и мемы |
