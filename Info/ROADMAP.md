# План развития YawaChat (Roadmap)

Главный рабочий план проекта. Все направления развития — от мелких правок
до крупных фич и монетизации — разбиты на **небольшие шаги (1 шаг = 1 коммит)**,
чтобы любую задачу можно было сделать за один присест, легко проверить и не
сломать работающее приложение.

Последний релиз: **2.2.9** (следующая версия в `VERSION` = **2.3.0**).
Детальные принципы дизайна и раскладки описаны в `ROADMAP-UI.md`.

---

## Правила работы по роадмапу

1. **Один шаг = одно небольшое изменение (1 коммит).** Не смешиваем несколько
   задач в одну правку. В начале коммита пишем номер шага (например, `1.8: ...`).
2. **Каждый шаг заканчивается рабочей сборкой:**
   - фронтенд: `npm run lint && npm test && npm run build`
   - C#-хост (если трогали `webview2/`): `dotnet build webview2/YawaChat.WebView2.csproj`
3. **Размеры шагов:**
   - **XS** — 15–30 минут (точечная правка в 1–2 файлах)
   - **S** — 1–3 часа (один компонент или один метод хоста)
   - **M** — полдня–день (связка хост + интерфейс)
4. **Статусы:** ✅ готово · 🔄 в работе · ⬜ не начато · ⏸ отложено.
5. **Документация для пользователя (`AGENTS.md`):**
   - Заметное пользователю изменение → короткий пункт простым языком в `CHANGELOG.md` + подъём `VERSION`.
   - Новая площадка или крупная возможность → обновляем `README.md`.
